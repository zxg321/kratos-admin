## 2. 产品背景与目标

### 2.1 背景
存量 gis2.0 已覆盖管网 GIS、采集、监测告警、巡检、指挥调度、设备档案六大业务域（约 200+ 表），但存在**双/三前端并存、模块直接依赖、同步 Feign 串联、空间分析依赖应用层、地图锁定高德 GCJ02、无智能能力**等架构债务。

### 2.2 产品定位转型
从「GIS 数据展示 + 多系统拼盘」→ **以管网数字资产为底座、事件驱动、AI 赋能的智能运维一体化平台**。

### 2.3 产品目标与成功指标
| 目标 | 指标（M0 目标值） |
|---|---|
| 一张图态势可视 | 全网设备/告警/巡检/应急实时上屏，刷新 < 3s |
| 一条链事件闭环 | 设备告警→派单→处置→归档全链路线上化率 100% |
| 一套数空间底座 | 空间资产入库完整度 ≥ 95%，空间分析计算 < 2s |
| AI 提效 | 巡检缺陷识别准确率 ≥ 85%，预测预警提前 ≥ 30min |
| 多云/多端投入收敛 | 前端收敛为 1 套 monorepo，废除 old_vue 与 global-store 混用 |

### 4.2 协作分层（一次数据生产到一次应急的端到端）

```
            ┌────────────── HTTP/REST │ gRPC ──────────────┐
            ▼                                            ▼
   ┌────── 统一前端 Admin Shell（S1–S8）────────┐   ┌─ 移动作业 APP(S9) ─┐
   │          态势总览(S8) 一张图(S1) 监测(S3)│   │  巡检/上报/处置/抄表  │
   │          巡检(S4) 调度(S5) 资产(S6) 采 集(S2)│   └─────────┬────────┘
   └──────────────┬──────────────────┘                             │
                  ▼                                                 │
   ┌──────────── API 网关 + BFF（认证/租户/审计/限流）────────────────┐
   │                                                                │
   │  S1 管网   S2 采集   S3 监测   S4 巡检   S5 调度   S6 资产   S7 系统 │
   │   └─────── 共享数据中台 ─────────┐                             │
   │   PostGIS(空间) + Timescale(时序) + Redis(状态) + MinIO(媒体)   │
   │   NATS/Kafka 事件总线  ◄──►  MQTT 设备上行链路(S3↔IoT设备)       │
   └──────────────┬─────────────────────────────────────────────┘
                  ▼
   ┌──────── AI 能力层（识别/预测/推演/派单/RAG/孪生） + 政企对接(S10) ─┐
```

- **以领域边界定义子系统**（Bounded Context），跨子系统仅通过 API 契约 + 事件总线交互，杜绝旧 `infrastructure` 跨模块强依赖。
- **数据中台统一**：空间资产统一落入 PostGIS，GIS 前端展示层薄化，空间计算全部下沉数据库。

### 4.3 关键事件流（跨子系统闭环）

- **采集→入库**：S2 导入批 → 空间校验 → 拓扑质检 → **NATS 事件** → S1 纳管 → 关联 S6 设备资产。
- **设备→告警→处置**：MQTT 设备上行 → S3 时序入库 → 规则引擎告警 → **事件** → S3 页面 / S5 指挥按等级派单 → S4/S9 巡检处置 → 回写归档。
- **隐患→巡检**：S9 隐患上报 / S4 AI 识别隐患图 → 生成工单 → 外业执行 → S4 复核登记 → 联动 S1 开挖影响区。
- **体系→演练→实战**：S5 预案数字化 → 演练 → 复盘报告 → 预案修订；BPM 全流程审批（S5/S6/S10）。

## 7. 非功能需求

- **性能**：页面首屏 < 2s；列表分页 < 500ms；空间分析 < 2s；大屏刷新 < 3s；设备实时数据端到端 < 3s。
- **可用性**：核心服务 ≥ 99.9%；移动端弱网可用、离线不丢。
- **安全**：登录 RSA-OAEP-256+A256GCM 加密；传输 TLS；租户越权防护；日志脱敏。
- **扩展**：设备协议插件化（MQTT/Modbus/HTTP），AI 模型可插拔；子系统可独立扩容。
- **可维护**：单域一服务、契约先行；生成代码走既有命令（buf/protoc/Wire），不手写伪产物。
