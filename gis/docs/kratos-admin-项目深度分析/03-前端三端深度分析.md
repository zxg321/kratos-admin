## TL;DR

- `frontend/` 是**三个相互独立的 pnpm workspace**（admin / uni-app / taro-app），各自独立 turbo + node_modules，互不共享依赖；统一遵循"**薄宿主 + 可发布 core/system/cli 包**"协议。
- admin：Vue 3.5 + Element Plus 2.14.5 + Vite 8 + TS 6，功能最完整（动态路由、按钮级权限、代码生成器、AI、消息中心）；宿主仅 4 个 src 文件。
- uni-app 与 taro-app 是**平行实现**（页面逐一对应，代码零共享）：前者 Vue3 编译链钉版（Vue 3.4/Vite 5）防漂移，后者 React 18 + Taro 4 + NutUI + zustand。
- 发布体系：10 个 `@liujitcn` npm 包（admin 3 + uni 3 + taro 4），版本齐步 0.0.48，源码+声明双发布。
- 最大技术债：**三端 core 大面积平行复制**（MFA/导航树/locales 机制三份），协议演进需三端同步；TS 版本三端割裂（6.0 / 各自钉版）。

## 1. Workspace 组织与包矩阵

| 包 | admin | uni-app | taro-app |
|---|---|---|---|
| core | kratos-admin-core | kratos-uni-app-core | kratos-taro-app-core |
| system | kratos-admin-system | kratos-uni-app-system | kratos-uni-app-system 对应 taro 版 |
| cli | kratos-admin-cli | kratos-uni-app-cli | kratos-taro-app-cli |
| ui | —（Element Plus 在 core 内） | —（uni-ui） | kratos-taro-app-ui（NutUI 适配） |
| 宿主 | apps/admin（private） | apps/uni-app | apps/taro-app |

- pnpm 版本按端分化（admin 10.33.4 / uni·taro 10.13.1），`packageManager` 字段锁定。
- admin 独有 `internal/`（vite-config、tsconfig、lint-config）供本仓宿主使用。

## 2. admin 端（管理后台）

- **技术栈**：Vue 3.5.42、vue-router 5.3.1、Pinia 3（persistedstate）、Element Plus 2.14.5（overrides 钉版）、Vite 8.0.14、TypeScript 6.0.3、vue-tsc 3、echarts 6、wangEditor、vue-i18n 11、vite-plugin-pwa。
- **薄宿主**：`apps/admin/src` 仅 main.ts（`bootstrapAdminApp({ modules })`）/ modules.ts / module-manifest.ts / vite-env.d.ts；模块清单唯一来源为 module-manifest.ts。
- **动态路由**：`core/src/routers/modules/dynamicRouter.ts` 的 `initDynamicRouter` 拉取后端菜单树+按钮列表，按 `<module>/<view>` 从模块 viewRegistry 解析懒加载组件；个人中心、AI、系统管理页面均由后端菜单动态注册。
- **权限**：按钮级 `v-hasPerm` 指令删除 DOM（`core/src/directives/modules/auth.ts`）+ useAuthButtons；策略判断在后端 Casbin，前端只消费按钮码。
- **RPC 层**：`src/rpc/**` 为 ts-proto 生成产物（DO NOT EDIT）；`api/*.ts` 手写封装走 axios（token 刷新/密码加密/MFA），core 与 system 各持 rpc/api 切片。
- **认证安全**：Cookie-only 模式——刷新令牌为 HttpOnly Cookie，访问令牌仅内存，不写 storage；启动清理旧版遗留持久化 token。
- **i18n**：四语言 JSON + generated.ts 注册表（含 dayjs/Element Plus 映射），registerLocaleMessages 校验语言键完整性；运行时语言集合由 `base_language` 接口决定。
- **特色功能**：代码生成器（views/tool/code-gen：表配置、proto 管理、代码预览、SSE 进度）、API 文档（内嵌 swagger-ui-dist）、锁屏。

## 3. uni-app 端

- 多端：H5（产物 `backend/data/uni-app`）+ 微信小程序；`@dcloudio/* 3.0.0-5010...` 刻意钉版。
- 请求封装：uni.request 拦截器（token/refresh、免鉴权白名单、同源代理、Accept-Language，`core/src/utils/http.ts`）。
- 分包：宿主 pages.json 含 bootstrap/index/login/protocal/status/webview/my；分包 `pagesMember/`（ai、message、profile、settings），页面实现位于 core/system 包的 `src/views/**`，由 core 的 pages.ts / Vite 插件生成 pages.json，带 recoverStalePageTransaction 事务恢复。
- system 页面：AI 对话（Composer/WelcomePanel/SessionDrawer/stream.ts）、消息中心、个人资料、设置。

## 4. taro-app 端

- Taro 4.2.1 + React 18.3.1 + NutUI React 3.0.20 + zustand 5 + webpack 5.91，自研 runner（`packages/core/dist/runner.mjs`）生成页面 wrapper/分包配置。
- 与 uni-app **页面一一对应**（同名页面 + pagesMember 同结构），但代码零共享，仅"模块协议"层面一致；额外多 ui 包（theme + NutUI icons）。

## 5. CLI 脚手架（三端）

- admin cli：`kratos-admin create` 基于 `templates/business-workspace` 模板（`__TOKEN__` 替换生成完整可发布 workspace），`--with` 装配已发布模块；`--kratos-project` 生成 `project-frontend`（Makefile + publish_packages.sh，H5 输出指向 backend/data/admin）与 Go 脚手架配合——**Go 侧仅传参调用 CLI**。
- uni/taro cli：不用文件模板，`src/index.mjs` 程序化生成，含 packed tarball 解压回归测试；uni cli README 明确"固定编译链版本避免漂移"。

## 6. 共享与复用设计

- 三端 core 是三份独立实现，无跨端共享代码；复用限于同一套模块协议（module.ts / module-manifest / viewRegistry / locales 注册 / rpc 目录约定）。
- 语言包自动发现闭环：主仓 generated.ts 由 `scripts/sync_locales.py` 生成；CLI 生成项目用 Node 版 sync-locales.mjs 扫描 `packages/modules/*/src/locales` 并强校验 zh-CN 一致性。
- core 抽象质量较高：package.json exports 细粒度，模块只能依赖 core 公开接口。

## 7. 构建与质量

- turbo 编排（依赖 `^build`）；发布构建 `scripts/build-package.mjs` 输出 dist/package，exports 指向源码形态（利于调试）。
- lint：admin 用 oxlint+prettier+stylelint+lint-staged+commitlint；uni/taro 用 eslint 9/8 + prettier。
- 测试：node --test（core：dict/menu/source-patterns/codegen-hmr；cli：tarball 回归）+ check:exports。
- 发布：10 个 @liujitcn 包版本齐步 0.0.48；uni/taro 包 files 白名单含 src（源码直发）；admin-vite-config 为 private。

## 8. 亮点与技术债

**亮点**
1. 薄宿主 + 可发布模块协议设计完整，CLI 一键产出与 Go 后端配套的前端 workspace。
2. i18n 键校验/自动注册闭环（含 Element Plus/dayjs 映射、运行时语言集合由 DB 决定）。
3. uni-app pages.json 生成 + 事务恢复；cli 有打包产物级回归测试。
4. 认证安全设计好（HttpOnly Cookie + 内存 access token）。

**技术债 / 风险（P0-P2）**
- **P1｜三端 core 平行复制**：navigation-tree、MFA 组件、locales 机制等三份实现，模块协议任何演进需三端同步修改，长期维护成本最高的一项。
- **P1｜编译链割裂**：admin 新链（Vite 8/TS 6）vs uni/taro 钉旧链（Vue 3.4/Vite 5），TS 版本三端不一致。
- **P2｜taro-app 构建产物疑似入库**：`apps/taro-app/dist/mp-weixin` 需确认 .gitignore 覆盖。
- **P2｜element-plus 依赖范围漂移隐患**：`^2.7.6` 靠 overrides 钉 2.14.5。
- **P2｜auditConfig 忽略的 CVE 清单**需持续人工维护。
- **P2｜rpc 生成产物在 core/system 多处重复存放**，proto 变更需多处再生成（已有统一 buf 配置缓解）。
