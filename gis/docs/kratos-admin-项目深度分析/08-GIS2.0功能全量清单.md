## TL;DR

- GIS2.0 是 GIS1.0 的**微服务化演进版**：9 个 Java 服务（Java 17 + Spring Boot 3.2.4 + Spring Cloud 2023 + Nacos + OpenFeign），Vue3 + micro-app 微前端（1 基座 + 9 子应用）+ 独立 pure-admin 总后台。
- 功能规模：约 **60+ Controller、150~160 张表（7 库）**；核心域为 GIS 管网（12 类覆盖物泛化建模 + 关阀/连通/拓扑/开挖/图形五类分析）、IoT（7+ 厂商 MQTT 适配 + TDengine 时序）、巡检闭环（12 Controller / 79 表）、两级租户 admin。
- 已有重构规划资产：`openspec/changes/` 两版迁移提案（go-kratos-vue3-refactor 绞杀者迁移 / go-kratos-v3-pg18-unified 统一底座），`deliverables/` 有 11 业务域 PRD、PipeMind AI Copilot PRD、GIS1×GIS2 对比。
- 主要技术债：双架构双 groupId 并存、iot_dev 停留 Spring Boot 2.6.11、空间分析全在 Java 应用层 O(N)（无 PostGIS）、明文凭据入 git、old_vue_gis2.0 冗余拷贝、maida_cnd 指挥调度"有表无码"半成品。

## 6. GIS2.0 相对 GIS1.0 的演进与缺口

- **已演进**：微服务化、收敛双巡检实现、overlayType 泛化吸收 1.0 冗余 CRUD、前端 Vue2→Vue3 微前端（与 04 号来源/优化列口径重复，明细见 04 号 F- 清单）。
- **未迁移缺口**：EAM、指挥调度 cnd（有表无码）、CAD 底图、二维码绑定、DMA 分区计量漏损分析——均为 SNOP 新建域需求源，处置以 04 号为准。

## 7. 技术债清单

1. 双架构并存：Spring Cloud 微服务 + SB 单体（iot_dev）+ 双 groupId（maida/…），维护心智负担大。
2. iot_dev 停留 Spring Boot 2.6.11；JUnit 3.8.1 / Springfox 2.9.2 停更依赖。
3. **空间分析全在 Java 应用层 O(N)**：无 PostGIS 空间索引/函数，管网规模增长后性能线性恶化。
4. 空间数据无 geometry 列（同 GIS1.0 模式）。
5. 明文凭据：yml 中数据库/MQTT 凭据、gaxc 等厂商密钥入 git。
6. old_vue_gis2.0 冗余整库拷贝；maida_cnd 半成品。

## ✅ 重构视角小结

| 资产 | 处置建议 |
|---|---|
| 覆盖物泛化建模 + 五类空间分析 | **最高价值**：proto 契约已在本仓 `gis/docs/20260913_管网域proto契约草案.md` 落地，算法重写为 Go 内存图 + PostGIS 混合（详见 09） |
| IoT 7+ 厂商适配链 + TDengine | Go 重写收益最大（并发模型适配 MQTT 高频消息）；时序可保留 TDengine 或迁 TimescaleDB |

| 两级租户 admin | 直接废弃，由全新自建 auth/acl 域覆盖（D4） |
| 指挥调度 cnd | 以 24 表 + Axure 原型为需求源，新建 cnd 域 |
| EAM/DMA（1.0 特有） | DMA 算法域重写；EAM 用 code_gen 快速重建 |
