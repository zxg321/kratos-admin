## TL;DR

- **定位**：本仓现状为多端管理平台底座（溯源素材）；目标态为智慧能源运营管理一体化平台 SNOP（ADR-12 D7），GIS 为首批子模块。
- kratos-admin 是一套**多端管理平台 monorepo**：Go + Kratos v3 后端 + Vue 管理端 + uni-app/Taro 双应用端 + 独立 GIS 子系统，外围有自研 kratos-core（宿主运行时）与 kratos-kit（组件库）生态。
- 核心架构哲学是"**Proto 即契约、生成即产物、模块即插件**"：Proto 驱动 HTTP/gRPC/OpenAPI/Agent Tool/MCP Tool/三端 TypeScript RPC 六类产物；后端以 `module.Module` 可插拔，前端以"薄宿主 + 可发布模块包"可插拔。
- 仓库明确定位为**系统底座而非业务系统**：内置认证/MFA/OAuth/租户/Casbin/消息/AI/代码生成/审计/备份等平台能力，不包含商城/订单/支付。
- 部署形态：后端应用容器化（admin 7001/6001、GIS 7002/6002），中间件复用宿主机（PostgreSQL+PostGIS/Redis/Consul/Vault）；前端 H5 产物随镜像发布由后端静态托管。

## 3. 四条架构主线

### 3.1 Proto 即契约（唯一事实源）
`api/proto` 同时驱动：Go HTTP/gRPC（buf 7 插件）、OpenAPI（4 语言 YAML）、Agent Tool / MCP Tool、三端 `src/rpc`（ts-proto，统一 Buf 配置在 `backend/api`）。接口改动强制按"Proto → 生成 → service/biz → 前端 RPC/页面 → 迁移权限"闭环，生成物禁止手改。

### 3.2 模块即插件（双端对称）
- 后端：`bootstrap.go` 公开 Resources/Modules/Tasks/Streams/Consumers 五类贡献，`adapter/core`、`adapter/kit` 与 internal 平级；外部 kratos-core 宿主合并 ProviderSet 即可托管 admin（外部生成代码不引用 backend/internal）。
- 前端：依赖方向恒为 `宿主 → 业务模块 → core`；宿主唯一维护 module-manifest，模块经 AdminModule/KratosAppModule/defineKratosTaroModule 声明页面与资源，构建期扫描合并。
- 三端 CLI 可各自生成完整外部 workspace，与 Go 脚手架（`--kratos-project`）配套。

### 3.3 平台能力底座（不是业务系统）
认证（密码+RSA-OAEP/AES-GCM 混合加密传输、JWT access/refresh、Cookie-only 前端策略）、MFA（TOTP/WebAuthn+恢复码+三级策略）、开放授权（租户绑定客户端、operation 白名单、IP 白名单、加解密 Filter）、审计（六类日志两级异步 + HMAC 文件兜底）、备份（AES-256+SHA-256/HMAC+OSS 回读校验）、i18n（语言包自动发现 + DB 动态翻译回退）、代码生成（表配置→模板→SSE 进度→菜单 SQL）。

### 3.4 安全与配置基线
Vault 根密钥统一派生（mfa/backup/oauth/log-fallback 各独立密钥路径），`ENC[...]` 密文配置，Vault 不可用启动失败不降级；prod 启动前六项外部安全能力声明校验；上传安全（MIME 嗅探、可执行类型拒绝、ClamAV 可选）。

## 4. 工程纪律

- **文档纪律**：docs/ 只写"已存在的能力"，规划中能力必须标"未实现"；README 四语言。
- **生成纪律**：api/gen、data/gen、wire_gen、前端 src/rpc、OpenAPI 均生成；`make check`（Backend→Frontend→i18n）+ `make i18n-check` 双门禁。
- **发布纪律**：`make tag` 强制 i18n 一致性 → 分支同步 → 测试打包 → 三组 tag → npm Trusted Publishing（10 包）。
- **迁移纪律**：唯一版本 v0.0.1、SQL 幂等、双方言同步维护、CI pglast 语法门禁。
