## 0. 契约概览（新增 4 个服务）

| 文件 | 服务 | 职责 | 对应目标表 |
| --- | --- | --- | --- |
| `overlay.proto` | `OverlayService` | 点覆盖物统一 CRUD + bbox + 列表（方案 B `gis_overlay`） | gis_overlay |
| `pipe.proto` | `PipeService` | 管道/管点 CRUD + DB 分析（关阀/连通/拓扑/开挖占位） | gis_pipe、gis_pipe_point |
| `collect.proto` | `CollectService` | 采集批次 + 采集点（导入数据、明细查询） | gis_collect_batch、gis_collect_point |
| `alarm.proto` | `AlarmService` | 告警配置 + 告警信息 | gis_alarm_config、gis_alarm_info |

> 空间分析与 `layer`/`feature` 衔接：覆盖物空间查询可复用 `AnalysisService`/`FeatureService`；管网图遍历（关阀等）作为 `PipeService` 上新 RPC，算子在 `internal/biz/analysis`（纯内存 Node-Edge 图，后续迭代落地）。

## 5. 落地步骤（writing-plans 拆解）

1. **评审本草案**：确认方案 B（`gis_overlay` 收敛）与 4 个 proto 的 message 字段。
2. **落 proto**：将上述 4 段写入 `gis/backend/api/proto/gis/admin/v1/{overlay,pipe,collect,alarm}.proto`。
3. **生成**：在宿主机执行 `make -C gis/backend gen`（生成 `api/gen`/`rpc`/OpenAPI）。
4. **迁移 SQL**：`gis/backend/migration/assets/v0.0.1/postgres/`，按 §表映射清单建 7 张表 + GIST 索引 + 中文注释。
5. **后端实现**：`internal/biz`（Overlay/Pipe/Collect/Alarm 业务）+ `internal/data`（GORM + PostGIS）+ `internal/service`（实现服务）。
6. **前端接入**：`gis/portal` 增加覆盖物图层加载/编辑、采集明细、告警列表；`frontend/admin` 增加设备/管网管理页。
7. **测试**：单测（图遍历算法纯内存） + 接口联调。

> 提示：本草案未生成代码，未跑 `make gen`，属"契约层设计产物"，字段可能与 codegen 需要微调（如 `optional` 与 validate 组合）；落地时以 `make gen` 报错为准修正。
