# 管网域表映射清单（legacy `maida_gis` → 目标 PostGIS `gis` 库）

- 日期：2026-09-13
- 范围：管网 GIS 主域，legacy 库 `maida_gis`（36 张表）中与管网/设备/覆盖物相关的表 → 目标 `gis` 库（PostGIS SRID 4326，表前缀 `gis_`，字段全中文注释）。
- 设计取向：遵循仓库"不向后兼容、优化系统设计"原则。legacy 点类覆盖物表高度同构（约 17 个公共字段 + 每类 3~8 个差异字段，字符型宽表、经纬度分离），故采用 **方案 B（推荐）：「线管道强类型 + 点覆盖物统一表」**；同时给出方案 A（贴近 legacy 分表）供权衡。

---

## 0. 设计说明

| 维度 | legacy | 目标（优化） |
| --- | --- | --- |
| 空间表达 | `longitude`/`latitude` decimal(10,6) 分离；管道用 text 存坐标串 | PostGIS `geometry(Point/LineString,4326)`，统一 `geom` 列 |
| 覆盖物定位 | `system_number`(10位) + `enterprise_id` 唯一 | `overlay_number`(兼容 system_number) + `tenant_id` 唯一 |
| 软删/临时 | `is_deleted`/`is_temporary` char(1) | `deleted_at`/`is_temporary` bool |
| 采集溯源 | `collect_data_id`/`collect_data_point_id`/`collect_worker`/`check_worker` 等 | 保留（采集批次与校核人），`collect` 域单独成表 |
| 时间戳 | `create_time`/`update_time``device_data_update_time` | `created_at`/`updated_at`/`data_updated_at`（GORM 维护） |
| 历史表 | 每设备一张 `_history` 镜像表 | 删除物理镜像表，统一走审计 + `base_table_archive` 归档 |

> 坐标系约束（项目约定）：库内一律 WGS84(4326)；前端展示转 GCJ02。迁移时 `longitude→ST_MakePoint(lng,lat)`，历史 `_history` 表不迁移，按归档策略处理。

## 2. 迁移执行要点

1. **表族收敛**：点类 11 张 + 8 张 `_history` → 1 张 `gis_overlay` + 归档；管线 2 张 → 2 张强类型表。
2. **空间建模**：所有 `geom` = `ST_SetSRID(ST_MakePoint(longitude,latitude),4326)`；管道线由管点排序构造 `ST_MakeLine` 并按 `pipe_id` 回填。
3. **租户映射**：`enterprise_id` → `tenant_id`；`resolveTenantScope` 统一过滤（非超管强制隔离）。
4. **幂等键**：`gis_overlay` 唯一键 `(tenant_id, overlay_type, overlay_number)`，规避 legacy 多库重复/重复筛选（`tools/重复筛选.sql` 思路）问题。
5. **迁移脚本组织**：`gis/backend/migration/assets/<version>/postgres/`，按 管线/覆盖物/采集/告警/索引 分文件；历史表不迁移。
6. **索引**：`geom` GIST 索引 + `(tenant_id, overlay_type)` + `overlay_number` 唯一索引。
