## 📌 TL;DR

- **商业形态**：**多租户 SaaS 云端订阅 + 私有化部署双轨**。标准客户走云 SaaS（按企业/套餐订阅）；大客户（水务/燃气集团、政府）走私有化交付（同一套代码，K8s 离线包）。
- **售卖模型**：`套餐(Plan) × 模块包(Module) × 计量维度（点位数/用户数/空间要素量）`；介质分型（燃气/水务/热力）= 行业模板，随套餐发放。
- **对 C 阶段的增量要求极小**：D4-D7 的租户体系、配置驱动、模块边界已天然 SaaS-ready；仅需在 P1 预留计量埋点。
- **路线**：C 完成（M4）→ D1 租户控制台与套餐/License → D2 Provisioning 自动化 + 白标 → D3 计费计量 → D4 开放生态/应用市场。

## 1. 产品分层

```text
SNOP 平台
├── 平台底座（必含）：登录/RBAC/租户/字典/文件/消息/审计
├── 模块包（按套餐选配）：
│   ├── GIS 核心包（一张图+五类分析）—— 旗舰功能，全套餐标配
│   ├── DMA 漏损包（水务增值）
│   ├── 巡检包 / IoT 包 / 指挥调度包 / EAM 包
│   └── Geo-Agent 包（AI 分析 Copilot，按调用量计量）
└── 行业模板（随套餐）：燃气版 / 水务版 / 热力版（字典+菜单+角色模板预置）
```

## 2. 租户模型升级（在 D4-D6 之上）

| 层级 | 机制 | 适用客户 |
|---|---|---|
| 标准租户 | 共库 + tenant_id 强隔离（现状设计） | SaaS 标准/进阶套餐 |
| 高级租户 | 独立 snop_* 库组（D6 机制现成，provisioning 自动建库） | 私有化/大客户专属库套餐 |
| 平台运营租户 | snop_system 内 `platform` 租户：套餐/License/租户生命周期管理 | 平台方自身 |

- **License 控制**：`platform` 租户签发 License（模块包 + 有效期 + 配额 + 签名）；各域中间件启动/请求时校验——超配额降级只读，过期锁定写。
- **Provisioning 流水线**（D2 阶段核心）：创建租户 → 发 License → 按介质模板初始化（角色模板/菜单/字典种子）→ 可选独立库组创建 → 通知开通。全 API 化，目标 5 分钟开一个企业。

## 3. 计费与计量（D3 阶段）

| 计量维度 | 采集点 | 说明 |
|---|---|---|
| 企业数/用户数 | system 域注册事件 | 套餐席位数 |
| IoT 点位数 | iot 设备注册事件 | 主计量维度之一 |
| GIS 要素量 | gis 要素写入事件 | 空间数据规模 |
| Geo-Agent 调用量 | MCP 网关计数 | AI 增值包 |
| 巡检任务量 | patrol 工单事件 | 行业包计量 |

- 计量事件经事件总线（Redis Stream，C 阶段已建）进 `platform` 计量聚合；月度出账单（先内部计费，接支付后置）。

## 6. 风险与对策

1. **过早计费化拖慢交付** → D1-D2 不做支付，只做 License/配额；支付后置到有种子客户后。
2. **嘈杂邻居（多租户性能）** → 事件总线削峰 + 套餐限流（网关按租户 QPS）；大客户独立库/实例。
3. **数据合规（能源行业涉密）** → 私有化双轨兜底；SaaS 客户合同明确数据边界；脱敏规则域现成可租户化。
4. **License 破解** → 签名校验 + 服务端定时复核（平台侧心跳），离线宽限期可控。
