# 第二部分 · 制作流程（怎么造）

## 2.1 功能标准生产流水线（每个功能走同一条线）

```text
① 契约先行     proto 编写（buf validate 语义校验 + 中文注释）         → 产物入 api/proto
② 生成         make gen：Go/gRPC/HTTP/OpenAPI/TS 类型/Agent+MCP Tool   → 生成物禁手改
③ 测试先行     TDD Red：黄金用例（业务规则测试 + 1.0/2.0 对拍用例）     → 先失败
④ 实现 Green   biz（业务）→ data（仓储，按域连库）→ service（薄适配）   → 用例转绿
⑤ 重构         消除重复、复杂度收敛；跨域只存 ID+契约取数（D6 纪律）
⑥ 前端对接     RPC 封装 → 页面（AMap 交互/表格表单）→ 按钮级权限 v-acl
⑦ SQL/文档同改 迁移 SQL（含中文注释）→ base_api 同步 → 文档更新
⑧ 评审         spec 合规 + 代码质量两级 review（Critical 阻断合入）
⑨ 合入         CI 全绿（build/test/lint/i18n 门禁）→ squash 合并
```

> 关键纪律：**契约不改不写码**；**测试不红不写实现**；**生成物零手改**；**跨库零 JOIN**。

## 2.3 并行开发组织（子代理/人力均可套用）

| 工作流 | 并行单元 | 依赖 |
|---|---|---|
| W1 底座线 | T1 骨架 → T2 建库 → T3 system 域（auth/RBAC 先行，其余域被阻塞） | 无 |
| W2 GIS 线 | T4 gis 迁入 → T5 五类分析（TDD 对拍）→ T6 MCP 注册 | T1、T2 |
| W3 前端线 | portal 迁入清理 → 登录/RBAC 界面 → 一张图/分析工具栏 | T3、T4 契约即可开工（mock） |
| W4 数据线 | T9 坐标 ETL 独立推进（黄金数据先行供 T5 对拍） | 无（可与 W1 并行） |
| W5 业务域线 | patrol/iot（P1）→ cnd/asset（P2） | W1 完成 + 各自契约冻结 |

> 冲突控制：同一 proto 文件/同一域目录同一时间只归一条工作流；契约变更走"提案→评审→生成→通知"。

## 2.4 质量门禁清单（CI 与人工）

1. `make check`：build + test + lint 全绿
2. 契约审查：proto 变更必附场景说明（Given/When/Then）
3. 黄金用例：五类分析/DMA 对拍 100% 通过
4. 权限用例：租户隔离/角色越权负向用例每域至少 1 条
5. 评审分级：Critical 阻断 / Major 限期 / Minor 记录
6. 缩放级验收：GIS 界面 18-20 级清晰度截图留档（T7）
